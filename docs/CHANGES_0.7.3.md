# v0.7.3：导出 PDF 的鼠标移入卡片修复

v0.7.2 的文字退出动作会先用原生 Hide 隐藏卡片；计时器不被阅读器支持时，无法恢复过渡。部分阅读器还会把鼠标进入事件交给视觉面板，旧面板没有取消关闭的事件。本次在实际导出的文件和 Chromium 原生 PDF 阅读器中复现了进入正文后消失的问题。

## 改动

- 文字、空隙和卡片共同组成连续阅读区域，覆盖右侧、左侧及上下避让布局。内部鼠标移动不会先隐藏卡片，视觉面板也会接住进入事件。
- 支持计时脚本时，真正离开后仍按用户要求在 250 ms 关闭；重新进入取消计时并保留当前图片。
- 不支持脚本但支持原生表单动作时，通过阅读区域外侧的透明控件自动关闭，无需点击 ×。鼠标直接跳出整张 PDF 页面时，这类阅读器无法收到页内事件；重新进入外侧区域或离开当前页时清理卡片。
- 保留网页同款卡片尺寸、原 PDF 页数、正文、照片和外框样式。

## 验证

- 71 项单元测试通过；类型检查、生产构建及 Vercel 使用的 `build:web` 通过。
- `tests/e2e/pdf.spec.ts` 通过：浏览器生成并下载 PDF，检查原页数、中文字体真实渲染；随后用 Chromium 原生 PDF 插件打开实际文件，鼠标在空隙和正文各停留超过 600 ms，验证翻图、自动关闭和重新打开。清空所有 JavaScript 后重复同一路径也通过。截图比较排除按钮页脚的阅读器焦点装饰。
- 私人项目在本地核对：2 页、11 条标注、22 张照片完整；说明文字和原始正文保留；标注区域之外的像素差异为 0。私人文件、照片和验证截图未提交仓库。
- 可选 `verify-pdf-hover.py` 使用的 PDFium 底层接口仍会把输入发送给隐藏字段，覆盖另一文字触发区的翻图按钮会导致该检查中止；此项不计为通过。完整 Chromium 阅读器的验证与该底层接口检查分开记录。

没有真实 WPS / Acrobat 应用测试环境。iPhone 微信聊天预览的原位图文弹层仍未实现，不以浏览器验证代替该入口验证。生产网址的部署状态需通过页面显示 v0.7.3 核对；已下载的旧 PDF 必须重新导出才包含修复。
