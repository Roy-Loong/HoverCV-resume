# PDF 和手机阅读链接

现有编辑器网址：**https://hover-cv-resume.vercel.app/**。把这个网址发给朋友，对方打开、上传自己的 PDF、添加标注、导出即可，无需注册或安装软件。此网址打开的是编辑器，不会把你的简历发给朋友。

## 给 HR 的两种阅读方式

- **电脑**：导出后点“下载悬浮交互 PDF”，用微信发送文件。支持 PDF 表单事件的阅读器可悬停展开卡片；卡片与网页共用 **360 × 420 CSS 像素**的尺寸定义，导出换算为 **270 × 315 PDF 点**，在标准 100% 显示时一致。阅读器缩放时，PDF 内的卡片随页面一起缩放；过小页面按相同比例缩小。每段文字分别定位，优先紧靠右侧。靠近页边时在原页内避让，不增加简历页数。卡片只绘制最外层边框，内部关闭/翻图按钮没有框；透明停留区域设为只读，避免点击标题产生整条表单焦点框。阅读器支持 JavaScript 计时器时，离开文字和卡片约 250 毫秒后自动关闭，移入卡片会取消关闭；旧的关闭回调不会误关重新打开的卡片。文字、文字与卡片间的空隙、卡片正文共同构成连续阅读区域，移动到正文或翻图按钮不会关闭。在支持原生表单动作但不支持计时脚本的阅读器中，移出整个阅读区域才立即关闭，无需点击 ×。如果鼠标直接跳出整张 PDF 页面，此类阅读器无法收到页内退出动作；重新进入页面外侧区域或离开当前页时会清理卡片。
- **手机**：手机没有鼠标悬停，改为点击彩色文字。部分手机 WPS / Acrobat 版本不执行 PDF 表单动作或脚本，网页代码无法替这些阅读器启用事件。可保留同一份 PDF，再发送“手机阅读链接”，对方点击网页中的彩色文字查看图文、翻图、关闭，无需登录。

**只发送一份 PDF 的限制**：在支持表单事件的手机阅读器中，可以在同一个文件里点击展开；但无法保证微信内置预览或所有手机 WPS / Acrobat 版本原位弹出图文。手机阅读链接是另一个可选功能，不等于已经满足“手机直接打开这份 PDF，所有交互都可用”。在未获作者接受前，不给悬浮 PDF 默认附加详情页或改成跳页浏览。

**iPhone 微信聊天直接预览**：本版本不能在这个入口原位展开图文卡片。文件现有的点击动作已包含不依赖 JavaScript 的原生 PDF Hide 动作；单纯去掉脚本、调整关闭延迟并不能让微信预览器执行它未支持的动作。图层开关、标准文字批注等方案同样取决于阅读器支持；标准文字批注也不能等同于当前图文卡片。没有经过该入口的真实验证，不将任何方案标为手机修复。这里的目标仍未实现，不用新增详情页、外部链接或强制手动关闭替代它。

两者区别：**体验网址**让朋友编辑自己的 PDF；**阅读链接**让 HR 阅读你发布的这份简历。阅读链接是当前版本的只读快照，之后修改编辑稿不会自动更改已发送的链接。

## 网站所有者开通手机阅读链接（只做一次）

这不影响现有本地编辑和 PDF 导出。原先的纯浏览器站点没有存储，无法仅凭推送源码生成能跨设备读取私人简历的短网址。

1. 打开 [Vercel 控制台](https://vercel.com/dashboard)，进入当前 `hover-cv-resume` 项目，找到 **Storage → Create / Connect Store → Blob**。创建或连接一个 **Public** Blob 存储，连接到项目的 **Production** 环境。确认自动增加了 `BLOB_READ_WRITE_TOKEN` 环境变量。只上传浏览器加密后的 `.hcv` 文件，原始 PDF 不上传。
2. 进入项目 **Settings → Environment Variables**，新增 **`SHARING_PUBLISH_KEY`**，值设为自己保留的一段至少 **16 个字符**的发布口令。选择 **Production** 并保存。不要加 `NEXT_PUBLIC_` 前缀，不要把值写入仓库或发给 HR。
3. 在 **Deployments** 中对最新 `main` 部署点击 **Redeploy**，等待 **Ready**。回到原网站，刷新至 **v0.7.0** 或更新版。点 **导出 → 手机阅读链接**，输入刚才的发布口令，点 **生成只读链接**，完成后点 **复制阅读链接**。将完整链接和 PDF 一起发给 HR。

如果界面提示“服务尚未开通”，检查上述两个变量是否属于 Production，并在添加变量后重新部署。Vercel 连接仍指向当前 GitHub 仓库和 `main`，无需再次导入或下载源码。开通需要网站所有者在 Vercel 的授权账户内操作；源码推送和本地测试不能替代这一步。

## 分享、更新与撤回

网页中的“生成只读链接”才会触发上传。发布口令仅用于许可上传和撤回，接收者无需填写。照片、说明和页面预览在浏览器中用随机 AES-256-GCM 密钥加密后直传 Blob，避免大型简历超过 Vercel 函数 4.5 MB 的请求限制。解密密钥放在链接的 `#` 后，不发送给网站服务端或存储。持有完整链接的人可阅读，请完整复制。

在原浏览器打开 **导出 → 手机阅读链接** 可以看到最近 10 个链接。修改简历后重新生成；需要撤回时输入发布口令，点该链接的 **撤回**。删除存储文件后，缓存最多约 1 分钟失效；已经下载或保存的副本不受影响。阅读页不提供编辑、原始 PDF 或项目 ZIP 下载，不会保存到接收者的编辑工作区。

## 验证范围

仓库自动检查包括：Chromium 原生 PDF 阅读器中打开实际导出文件，悬停后在空隙停留、进入正文、翻图、移出自动关闭、重新打开，并对清空 JavaScript 的同一文件重复验证；PDFium 底层表单动作检查；250 ms 计时状态与重新进入取消关闭；中文字体实际渲染；iPhone / Android 尺寸与触屏事件的 Chromium 浏览器模拟；加密链接的只读阅读页与错误、篡改、撤回状态；上传许可和撤回权限。没有真实 iOS / Android 的 WPS、Acrobat 或微信应用测试环境，不能把浏览器模拟或 PDFium 结果称为这些应用已经实测通过。

原生检查另有一项明确限制：所用 PDFium 底层表单接口仍向隐藏的文字触发区发送鼠标事件。因此卡片正文覆盖另一处文字触发区的点击，脚本仅检查底层触发区已隐藏，并计入 `hidden_input_cases_unverified`；不算作点击验证通过。翻图按钮覆盖隐藏触发区时，底层检查也可能错误切到另一张卡片并中止。原生 Chromium 阅读器的实际鼠标与截图测试单独验证这些操作，不将底层接口失败称为 WPS / Acrobat 已通过。其余正文区域会检查点击后卡片保持打开、透明区域未获得焦点。WPS / Acrobat 仍需对应应用复核。

实际 Blob 上传、跨设备打开和在线撤回，仍需网站所有者完成上面的 Vercel 连接后再验证。
